# PlayDropCore (local Swift package)

The Rust core (`crates/playdrop-core` through `crates/playdrop-ffi`) packaged for the iOS
app. Only the app target links it; the share extension never does (it cannot host the core
and must stay small).

Two parts, both generated by `apps/ios/scripts/build-core.sh` on a Mac and never committed
(see `apps/ios/.gitignore`):

| Path | What it is |
|---|---|
| `PlayDropCoreFFI.xcframework/` | `libplaydrop_ffi.a` for `aarch64-apple-ios` (devices) and `aarch64-apple-ios-sim` (Apple silicon simulators), each with `Headers/PlayDropCoreFFI/PlayDropCoreFFI.h` and `module.modulemap` (the C module `PlayDropCoreFFI`) |
| `Sources/PlayDropCore/PlayDropCore.swift` | The UniFFI 0.32 Swift bindings (module `PlayDropCore`, set by `crates/playdrop-ffi/uniffi.toml`), generated in library mode from the host `libplaydrop_ffi.dylib` |

`Package.swift` declares the XCFramework as the binary target `PlayDropCoreFFI` and the
bindings as the Swift target `PlayDropCore` that depends on it. App code imports
`PlayDropCore` only, and only `PlayDrop/Core/` uses it directly (`CoreHost` is the facade).

Rebuild after every change under `crates/`:

```sh
cd apps/ios
scripts/build-core.sh            # release, device and simulator
scripts/build-core.sh --sim-only # simulator only, quicker
```

When either part is missing, Xcode fails while resolving this package or at the app's
"Check the Rust core is built" build step; both messages point back to `build-core.sh`.

The Rust static library has no Apple framework dependencies (checked with `cargo tree` for
`aarch64-apple-ios`: no `core-foundation`, `security-framework` or `system-configuration`),
so the app needs no extra linker flags for it.
